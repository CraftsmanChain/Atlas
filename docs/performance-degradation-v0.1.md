# Atlas 性能衰减检测 v0.1

> 模块版本：`degradation-v0.1.0`  
> 运行模式：`shadow`  
> 更新日期：2026-07-23

## 目标与边界

首版在不占用 GPU、不登录节点、不干扰业务任务的前提下，从现有 Feature Catalog 快照中筛出值得人工复核的 GPU 性能衰减候选。

候选不是故障结论、健康扣分或校准后的故障概率。Atlas 不会根据候选自动隔离 GPU，也不会自动运行压力测试。确认工作负载具有可比性后，才可在人工批准的维护窗口执行 DCGM 或 SuperBench 复测。

## 输入与判定

| 项目 | v0.1.0 契约 |
| --- | --- |
| 实体与粒度 | 单 GPU，读取当前健康评分关联的 Feature Catalog snapshot |
| 负载条件 | `gpu_util_avg_15m >= 80%` |
| 性能观测 | `sm_clock_avg_15m > 0` |
| 时效 | 快照源时间距评估时间不超过 1 小时；过期快照不参与候选判断 |
| 数据质量 | 健康快照数据置信度为 A 或 B |
| 首选基线 | 同节点、同型号、排除自身，至少 3 个 peer |
| 兜底基线 | 同型号集群、排除自身，至少 4 个 peer |
| 稳健统计 | peer SM 时钟中位数 |
| 候选阈值 | `observed_clock / peer_median < 0.85` |
| 输出状态 | `candidate`，仅影子观察 |

置信度按数据源置信度、peer 数量和基线范围分级。完整 8 卡节点的 7 个同机 peer 且源置信度为 A 时可输出 A；样本较少或使用集群兜底时下调。数据不足不会被当作性能正常或性能衰减。

## API

- `GET /api/v1/degradation/summary`
  - 输出模块版本、模式、已评估/高负载可评估/基线就绪/候选 GPU 数、门槛、时效 SLA、型号分布、最新源时间和评估时间。
- `GET /api/v1/degradation/candidates`
  - 输出 GPU 身份、型号、利用率、观测和基线时钟、性能比、peer 数量、基线范围、置信度、证据、特征版本和建议动作。

两个接口均为只读；每次请求基于当前持久化快照重新评估，不写入健康分或故障事件。

## 安全规则

1. 空闲或低负载 GPU 不参与候选判断。
2. peer 不足时不生成候选。
3. 候选不进入健康评分、问题统计或故障概率。
4. 主动测试必须经过维护窗口、无计算进程、操作确认、超时和温控保护。
5. 页面明确展示 `SHADOW MODE` 和人工核验要求。

## 已知限制与后续

- 利用率相同不代表工作负载相同，SM 时钟差异也可能来自功耗上限、P-state、应用阶段或采样窗口；因此 v0.1.0 只能生成待核验候选。
- 当前只覆盖 SM 时钟，没有宣称计算吞吐、显存带宽、PCIe 或 NVLink 已完成检测。
- 后续应补充功耗/温度/throttle 条件化、历史稳定基线、工作负载上下文，并建立维护窗口 GEMM、显存、PCIe、NVLink/NCCL 分类复测与维修后验证记录。
